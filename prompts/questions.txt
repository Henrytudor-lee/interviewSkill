## ⚠️ 候选人画像判断（出题前必做，**严格按简历事实**）

**第一步**：从简历中判断候选人类型（不要看岗位要求里的年限，只看简历事实）：

| 候选人类型 | 简历特征 |
|---|---|
| **应届毕业生** | 包含"XX大学 / 大专 / 学院"、"在校"、"XX届"（如"2024届"）、"学生"、"应届"、"实习"等关键词；**无正式全职工作经历**，或仅有 1-2 段实习 |
| **初级（0-3 年）** | 1-2 段正式全职工作，每段 1-2 年；工作内容偏执行 / 辅助；简历长度较短 |
| **中级（3-5 年）** | 2-3 段工作经历，至少一段 ≥2 年；开始有项目主导 / 独立负责经验；掌握多项核心技能 |
| **高级（5+ 年）** | 多段工作经历，有架构设计 / 团队管理 / 复杂项目（高并发、大规模）经验；简历中频繁出现"主导"、"架构"、"团队"等关键词 |

判断方法：
- 简历里有"XX届"+"在校/学生" → 应届生
- 简历里只有"实习"段且无全职 → 应届生
- 工作起止时间累计 < 3 年 → 初级
- 累计 3-5 年 → 中级
- 累计 > 5 年 → 高级

**第二步**：根据候选人类型调整题目风格（**题目难度必须与候选人画像匹配**）：

| 候选人类型 | 客观题方向 | 主观题方向 |
|---|---|---|
| **应届毕业生** | 基础概念、专业基础、学习方法（如"解释 HTTPS 握手"、"TCP 三次握手"、"MVCC 原理"） | 实习 / 课程项目经历、学习方法、潜力展示、岗位认知 |
| **初级（0-3 年）** | 核心技能熟练度、工具使用、基础原理 | 具体项目职责、问题解决案例、工具掌握程度 |
| **中级（3-5 年）** | 进阶技能、最佳实践、原理深度、踩坑经验 | 复杂项目主导、跨团队协作、技术选型理由 |
| **高级（5+ 年）** | 系统设计、架构权衡、底层原理、性能优化 | 架构决策、技术团队管理、业务影响、行业洞察 |

**重要原则**：
- ❌ 不要给**应届生**出系统设计、架构权衡、高并发方案等高级题
- ❌ 不要给**高级工程师**出"什么是 HTTPS"、"什么是 TCP"等基础概念题
- ✅ 题目难度要让候选人"踮脚能够到"——既不简单到侮辱智商，也不难到完全答不上

## 出题要求

### 客观题（6 道）— 全部简答题
- 围绕岗位核心技能，覆盖关键技术点
- **题目难度与候选人画像匹配**（见上表）
- 仅限简答题形式（严禁 ABCD 选择题、判断对错题、代码题、场景方案题）

### 主观题（5 道）
- 必须结合候选人简历中的**具体经历**（项目名、技术栈、职责）
- **应届生**：实习 / 课程项目、学习方法、岗位认知
- **有经验者**：项目主导经验、问题解决、技术选型

## 答案要求（每道题必填 answer 字段）

- **客观题答案**：1-3 句话给出**标准答案**，可直接用于面试评分。简短、完整、可判定对错。
- **主观题答案**：3-5 条**评估要点**，列出候选人回答时应包含的关键点（用"· "开头），便于评估深度。

## 输出格式（严格 JSON）

{
  "candidateLevel": "应届生 | 初级 | 中级 | 高级",

  "questions": [

    { "type": "主观", "question": "题目描述", "answer": "评估要点（3-5 条）" }
  ]
}

直接输出 JSON，不要任何思考或解释。think 块不超过 30 字。
